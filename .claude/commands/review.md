# Code Review Command

## Что делать при вызове /review

### 1. Получить последние изменения
- Выполни `git log --oneline -10` чтобы увидеть последние коммиты
- Выполни `git diff HEAD~3 HEAD --stat` чтобы увидеть какие файлы менялись
- Выполни `git diff HEAD~3 HEAD` чтобы получить полный diff последних 3 коммитов
- Если есть unstaged changes — включи их через `git diff` и `git status`

### 2. Архитектурный анализ
Проверь в изменённых файлах:
- Нарушение separation of concerns (бизнес-логика в роутерах, прямые DB запросы вне сервисов)
- Циклические зависимости между модулями
- Неправильные уровни абстракции
- Нарушение существующих паттернов проекта

### 3. Функциональный анализ
Проверь:
- Корректность обработки ошибок (особенно API calls к Bybit/Binance)
- Race conditions в асинхронном коде
- Утечки памяти (незакрытые соединения, подписки без unsubscribe)
- Граничные случаи которые не обработаны

### 4. Быстрые фиксы — делай сразу молча
Без вопросов исправляй:
- Задублированный код (одинаковые функции/блоки)
- Неиспользуемые импорты
- Пустые функции и мёртвый код
- console.log оставшиеся от дебага
- Очевидные опечатки в названиях переменных/функций

### 5. Баги и проблемы — докладывай и предлагай в роадмап
Если находишь что-то серьёзное:
- Опиши проблему чётко: что, где, почему это баг
- Оцени приоритет: Critical / High / Medium
- Спроси: "Занести в ROADMAP?"
- Если пользователь говорит да — добавь в ROADMAP.md в секцию Bugs

### 6. Финальный отчёт
После анализа выведи:

```
## Review Summary

✅ Автоматически исправлено

[список того что пофиксил]

⚠️ Найденные проблемы (требуют решения)

[CRITICAL/HIGH/MEDIUM] Описание — предложить в роадмап? (да/нет)

🏗️ Архитектурные замечания

[список наблюдений без срочного действия]

📊 Изменения покрыты ревью

Коммиты: X..Y
Файлов проверено: N
```
