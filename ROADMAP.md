# ROADMAP

Список запланированных улучшений проекта, приоритизированных по соотношению усилий и эффекта.

---

## Приоритет 1 — Улучшить промпт Claude ✅
**Статус:** Выполнено

**Проблема:** Claude получает слишком мало контекста — только 20 сырых OHLCV-свечей и 4 числа OBD. Без вычисленных метрик модель не может адекватно оценить рыночную ситуацию.

**Решение:**
- Вычислять RSI(14) из свечей на бэкенде перед вызовом Claude
- Передавать объёмный тренд (растёт / падает за последние 5 свечей, %)
- Передавать направление последних 3 candle bodies (bullish/bearish/doji)
- Передавать ATR(14) для контекста волатильности
- Добавить в системный промпт чёткие правила интерпретации этих метрик

## Приоритет 2 — Фильтр сигналов по confidence ✅
**Статус:** Выполнено

**Проблема:** Telegram-уведомление уходит на любой не-WAIT сигнал, даже с confidence=5. Это создаёт шум и снижает доверие к сигналам.

**Решение:**
- Добавить поле `minConfidence` в таблицу `Settings` (default: 65)
- Отправлять Telegram только если `confidence >= minConfidence`
- Отображать в UI бейдж уверенности с цветовой кодировкой (красный < 50, жёлтый 50–70, зелёный > 70)

## Приоритет 3 — Multi-timeframe контекст для Claude ✅
**Статус:** Выполнено

**Проблема:** Система смотрит только на 1m свечи. Claude не знает, что происходит на старших таймфреймах — сигнал против тренда 15m должен получать низкий confidence.

**Решение:**
- Перед вызовом Claude подтягивать 20 свечей на `5m` и `15m` через Binance REST
- Передавать Claude направление тренда на каждом таймфрейме (определять по EMA или просто по положению закрытия относительно средней)
- Добавить в промпт инструкцию: сигнал против старшего тренда → понижать confidence

## Приоритет 4 — Корректная цена входа для трекинга
**Статус:** Не начато

**Проблема:** `signal.price` фиксируется в момент OBD-паттерна. Claude отвечает через 10–30 секунд — к этому времени цена меняется. Трекинг WIN/LOSS считается от некорректной цены входа.

**Решение:**
- После получения ответа от Claude (direction != WAIT) делать REST-запрос за актуальной ценой (`/api/v3/ticker/price`)
- Обновлять `signal.price` этой актуальной ценой
- Пересчитывать SL/TP с учётом нового ценового уровня (если Claude вернул относительные смещения)

## Приоритет 5 — SHORT-сигналы ✅
**Статус:** Выполнено

**Проблема:** Система детектирует только LONG (просадка OBD + отскок). В даун-трендах и боковых рынках это приводит к большому числу убыточных сигналов. Логика трекинга для SHORT уже готова.

**Решение:**
- В `engine.js` добавить детекцию инвертированного паттерна: все 4 OBD резко выросли (spike) затем начали падать → сигнал SHORT
- Добавить отдельный `dipThreshold` для SHORT или использовать тот же
- Проверить корректность P&L-расчёта в `tracker.js` для SHORT-направления

## Приоритет 6 — Бэктестинг на реальных данных
**Статус:** Не начато

**Проблема:** Неизвестно насколько хорошо работает стратегия OBD исторически. Сигналы оцениваются только в реальном времени, нет возможности проверить стратегию на прошлых данных до запуска с реальными деньгами.

**Решение:**
- Загружать исторические данные order book с Binance (или через `data-api.binance.vision`)
- Прогонять `detectSignal()` на исторических снапшотах OBD
- Рассчитывать статистику: winrate, средний PnL, максимальная просадка, Sharpe ratio
- Отображать результаты в отдельной вкладке UI с графиком эквити

---

## Приоритет 7 — Автоматическое исполнение сделок по сигналу
**Статус:** Не начато

**Проблема:** Сейчас торговля только ручная — Claude даёт сигнал, пользователь сам нажимает "купить". Это убивает скорость реакции на 1m-сигналы.

**Решение:**
- Добавить в Settings флаг `autoTrade: boolean` и `autoTradeAmount: float` (сумма в USDT на одну сделку)
- После Claude-подтверждения с confidence >= minConfidence автоматически вызывать `placeOrder` с OCO-ордером (TP/SL от Claude)
- Добавить лимит открытых позиций (`maxOpenTrades`) для управления риском
- Добавить kill-switch через UI для экстренной остановки
